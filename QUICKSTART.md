# Локальный стенд с нуля

Разворачиваем DataLens с нашими доработками (права на папки и книги, тестовый вход по почте) на своей машине, чтобы потыкать руками. Всё крутится в Docker, на хост ставить ничего не нужно, кроме git.

## Что нужно

- Linux или macOS. На Windows тоже можно, но только внутри WSL2.
- Docker с Compose v2: команда `docker compose version` должна работать. На Mac это Docker Desktop.
- Оперативная память для Docker: минимум 8 ГБ, лучше 10. Сборка интерфейса прожорливая. На Mac лимит задаётся в Docker Desktop → Settings → Resources.
- Свободный порт 8080.
- Диск: 10–15 ГБ под образы и зависимости.

## 1. Склонировать четыре репозитория рядом

Именно рядом, в один каталог: скрипт запуска ищет соседей по относительным путям. Ветка `acl` обязательна во всех четырёх, в `main` доработок нет.

```sh
mkdir datalens-local && cd datalens-local
git clone -b acl git@github.com:romashuhov/datalens.git
git clone -b acl git@github.com:romashuhov/datalens-us.git
git clone -b acl git@github.com:romashuhov/datalens-ui.git
git clone -b acl git@github.com:romashuhov/datalens-auth.git
```

Должно получиться:

```
datalens-local/
  datalens/        <- отсюда всё запускается
  datalens-us/
  datalens-ui/
  datalens-auth/
```

## 2. Включить доработки

В каталоге `datalens` создать файл `.env` с тремя строками:

```sh
OBJECT_ACL_ENABLED=true
ACL_ROOT_DEFAULT_ROLE=none
AUTH_DEV_LOGIN_ENABLED=true
```

Пароли и ключи скрипт сгенерирует и допишет в этот же файл сам.

## 3. Запустить

```sh
cd datalens
./init.sh --dev --dev-env --dev-us --dev-auth --dev-ui --dev-build
```

Первый запуск долгий, 10–20 минут: контейнеры ставят зависимости и собирают интерфейс. Прогресс:

```sh
docker compose -f docker-compose.dev.yaml logs -f ui auth us
```

Когда в логе `ui` появится сообщение об успешной сборке, открывайте http://localhost:8080. Повторные запуски быстрее, `--dev-build` можно уже не указывать.

## 4. Войти

- **Админ:** логин `admin`, пароль в `datalens/.env` в строке `AUTH_ADMIN_PASSWORD`. Обычная форма входа.
- **Все остальные:** под формой входа есть блок «Тестовый вход (без пароля)». Любая почта, например `ivan@test.local`, и кнопка. Учётка создаётся сама. Галочка «Выдать роль editor» включена по умолчанию: с ней пользователь может создавать папки в корне.

## 5. Что потестировать

1. Войдите тестовой почтой, создайте папку, внутри книгу, в ней дашборд.
2. На папке нажмите ⋮ → «Доступ». Выдайте другой почте роль Viewer или Editor. Чтобы почта появилась в списке для выбора, этим пользователем нужно хотя бы раз войти.
3. Откройте приватное окно браузера, войдите второй почтой. Видно только выданное, соседние папки скрыты, при Viewer редактировать нельзя.
4. Поиграйте с переключателем «Наследовать права от родительской коллекции» и с ролью «Нет доступа». «Нет доступа» на папке закрывает всё внутри, даже если ниже что-то выдано.
5. Заведите третью почту со снятой галочкой editor: у неё пустой корень, создавать нельзя, пока кто-то не пустит.

Правила прав подробно: [datalens/docs/acl.md](datalens/docs/acl.md). Тестовый вход и сценарий по шагам: [datalens/docs/dev-login.md](datalens/docs/dev-login.md).

## Остановить

```sh
./init.sh --stop          # остановить контейнеры
./init.sh --down          # остановить и удалить контейнеры, данные в базе останутся
./init.sh --rm-volumes    # снести и данные тоже
```

## Важно

С `AUTH_DEV_LOGIN_ENABLED=true` кто угодно входит кем угодно. Это только для локальной машины, на общий сервер так не выкладывать.

Проверено на Linux (WSL2). На Mac должно работать так же, потому что всё внутри Docker, но первый запуск там стоит делать с открытыми логами. Если что-то не поднялось, присылайте вывод команды с логами.
